# Local development

Use Python 3.11+ and a virtual environment. Run commands from the project root.

## PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m pip install --no-deps -e .
.\.venv\Scripts\python.exe scripts/configure.py
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD\data\browsers"
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m app.cli create-user admin
.\.venv\Scripts\python.exe -m app.dev
```

## Linux/macOS

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.lock
python -m pip install --no-deps -e .
python scripts/configure.py
PLAYWRIGHT_BROWSERS_PATH="$PWD/data/browsers" python -m playwright install chromium
python -m alembic upgrade head
python -m app.cli create-user admin
python -m app.dev
```

Linux may need `python -m playwright install --with-deps chromium` to install OS
libraries. For a self-contained browser runtime, prefer the Docker setup in README.

`app.dev` runs API, demo source and worker as independent child processes; Ctrl+C
stops them. SQLite must use one worker process. Migrations are explicit: API and
worker never create or upgrade tables themselves. The wheel contains application
packages/assets; migration and operational commands require a source checkout.

## Existing local demo compatibility

The public application and Python package are named **Rowstead**. Existing local
demos retain `batchflow` as the Compose project/image and PostgreSQL database name,
legacy database/storage paths, and `BATCHFLOW_*` helper environment variables.
These technical identifiers stay unchanged to preserve existing local demo data
and commands. They do not change the public brand or package name.

## Settings

The app reads only `.env` in the working directory. Environment variables take
precedence; parent directories are not searched for another project's secrets.
The helper preserves an existing `.env`; compare `.env.example` for new settings.

| Variable | Default / purpose |
|---|---|
| `DATABASE_URL` | `sqlite:///./data/batchflow.db`; Compose supplies private PostgreSQL |
| `SESSION_SECRET` | Required, at least 32 random characters; generated by configure.py |
| `POSTGRES_PASSWORD` | Random URL-safe password used by Compose |
| `DEMO_BASE_URL` | `http://127.0.0.1:8001`; Compose supplies its internal source name |
| `STORAGE_DIR` | `data`; original files stay outside the webroot |
| `WORKER_CONCURRENCY` | 2 on PostgreSQL; SQLite forces one thread |
| `WORKER_POLL_SECONDS` | 1 |
| `LEASE_SECONDS` | 120; heartbeat renews active claims |
| `MAX_ATTEMPTS` | 3 per processing cycle |
| `MAX_UPLOAD_MB` | 20; parser also enforces a fixed safety cap |
| `COOKIE_SECURE` | false on localhost; enable with HTTPS deployment |
| `PLAYWRIGHT_BROWSERS_PATH` | Example uses `data/browsers` for local installs |

No admin credentials are bundled. Create an account interactively, or supply
`BATCHFLOW_ADMIN_PASSWORD` in the environment for noninteractive account creation.
Passwords are hashed in the database.

## Checks

```sh
python -m ruff check .
python -m pytest -q
```

Set `TEST_DATABASE_URL` to a dedicated PostgreSQL test DB, or use
`python scripts/test_postgres.py` with Compose running. Each PostgreSQL test uses
its own temporary schema.

PowerShell browser E2E:

```powershell
$env:BATCHFLOW_E2E = '1'
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD\data\browsers"
.\.venv\Scripts\python.exe -m pytest -q tests/test_ui_e2e.py --basetemp=artifacts/pytest-e2e
```

POSIX equivalent:

```sh
BATCHFLOW_E2E=1 PLAYWRIGHT_BROWSERS_PATH="$PWD/data/browsers" \
  python -m pytest -q tests/test_ui_e2e.py --basetemp=artifacts/pytest-e2e
```

The E2E test creates isolated data and starts API/source/worker on ephemeral local
ports. It does not use your real account or task database.
